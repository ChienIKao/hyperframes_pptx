# 資訊圖表：內容 → 元件對照

歸納自常見的研究型／提案型簡報版型。原則是**一頁一個視覺主角**：先判斷這頁的內容屬於哪一型，再挑對應的元件，而不是把文字條列搬上去。

整理 `deck.md` 時（Step 1），逐頁問：「這段內容是在並列、比較、演進、流程、數字，還是結論？」

| 內容型態 | 常見做法 | 用這個元件 |
|---|---|---|
| 多個並列的實例（產業案例、廠商、專案） | 右側堆疊卡片，左上角斜貼標籤（如「回訪率提升」），卡片右側放 logo | ` ```cards stack ` + `tag:` + `img:` |
| N 個問題／痛點／亮點 | 三張並排卡片，每張一個圖示＋標題＋一句說明 | ` ```cards ` + `icon:` |
| 狀態轉變（被動 → 主動、傳統 → 新方案） | 圓圈＋箭頭的演進鏈 | ` ```flow vertical ` |
| 系統流程／資料管線 | 方塊＋箭頭橫向流程 | ` ```flow ` |
| 方法的執行步驟 | 帶編號圓圈的步驟清單 | ` ```steps `（直向）／` ```timeline `（橫向） |
| 關鍵數字（維度、改善幅度、樣本數） | 大數字＋小標籤 | ` ```stats ` |
| 多方法 × 多特性比較 | ○ × 矩陣表格 | Markdown 表格（○ × 自動置中） |
| 兩個方案對比 | 左右兩欄 | ` ```compare `（兩欄時自動加 VS） |
| 實驗結果數據 | 長條圖、折線圖 | ` ```chart column / bar / line / pie ` |
| 承先啟後的關鍵句 | 置中大字，關鍵詞用色塊強調 | 只有段落＋`==關鍵詞==` → 自動成為「宣言頁」 |
| 公式註解、符號說明、本頁結論 | 底部色塊提示框（「註：…」） | `> [!NOTE]`、`> [!IMPORTANT]`、`> [!TIP]` |
| 引用出處 | 頁尾小字「資料來源：…」 | 以「資料來源：」開頭的段落 |
| 截圖、架構圖、實驗圖 | 加框＋圖說 | `![圖說](assets/x.png)` |
| 金句／研究核心價值 | 單獨一頁 | 只有一個 `>` 引言 → 引言卡片頁 |

## 版面組合規則

- **左文右圖**：一頁同時有文字與一個元件時，文字在左（約 42–45%），元件在右。最常見的版型。
- 左欄文字 **≤ 5 條**；更多就拆頁，或把細節移到講者備註 `<!-- -->`。
- 同頁最多一個元件（兩張圖片可並排）；多出來的元件會自動各自成頁。
- 提示框放在頁面底部、橫跨全寬；每頁最多一個。

## 寫法速查

~~~markdown
#### 消費習慣的轉變 | 產業趨勢

外帶與線上點餐快速成長，門市面臨==人力==與==數位化==的雙重壓力。

- 人力不足：**尖峰時段出餐延遲**
- 缺乏數據：**備料全憑經驗判斷**

```cards stack
- 連鎖品牌 A | 會員 App、行動支付、集點 | tag: 回訪率提升 | img: assets/logo-a.png
- 獨立咖啡館 B | 線上預訂、到店取餐 | tag: 零排隊
```

> [!NOTE] 等候時間以點餐到取餐計算。

資料來源：作者整理。
~~~

## 元件項目語法

每個元件區塊內是條列，每一項以 ` | ` 分欄：

```
- 標題 | 說明 | 第三欄… | tag: 標籤 | img: 路徑 | icon: 圖示字
  - 子項目（卡片／比較欄內的條列）
```

| 元件 | 標題 | 說明 | 第三欄以後／子項目 | 參數（接在元件名後） |
|---|---|---|---|---|
| `cards` | 卡片標題 | 一句說明 | 條列細節 | `stack`、`grid`、`cols=3` |
| `steps` / `timeline` | 步驟名 | 說明 | 條列細節 | `vertical`、`horizontal` |
| `flow` | 節點名 | 小字說明 | — | `vertical`、`horizontal`；也可寫成單行 `A -> B -> C` |
| `stats` | 數字（如 `38`、`3.8%`） | 標籤 | 補充說明 | — |
| `compare` | 欄標題 | 欄副標 | 子項目＝該欄條列 | — |
| `chart` | — | — | 內容是 Markdown 表格：第一欄類別，其餘欄為數列 | `column`／`bar`／`line`／`pie`／`doughnut`／`stacked`，後面接圖表標題 |

## 禁止事項

- **不捏造數字。** `stats`、`chart` 的數值一定要來自使用者的稿子；沒有就用 `— 數值 —` 佔位，並在回報時列出。
- 不為了「有圖」而硬套元件：純論述的內容就用條列。
- 「照稿直出」模式下，把條列改成元件屬於**改版面、不改內容**，可以做；但刪減或改寫文字要先問。
